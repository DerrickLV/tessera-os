# Security policy

## Reporting a vulnerability

Do not open a public issue containing vulnerability details, credentials, client
information, or exploit material. Report suspected vulnerabilities privately to the
repository owner through GitHub's private vulnerability reporting channel when it is
enabled, or through the organization's approved security contact.

Include the affected commit, component, reproduction steps using synthetic data,
impact, and any suggested containment. Never test against production systems or real
client data without written authorization.

## Response expectations

The owner will acknowledge receipt, classify severity, disable affected capabilities
when necessary, preserve audit evidence, and coordinate remediation and disclosure.
No production capability may be restored until the responsible owner approves the
fix and regression evidence.

## Supported versions

Only the current `main` branch is supported. Tessera OS remains an offline and
pilot-oriented foundation until its documented production gates are satisfied.
